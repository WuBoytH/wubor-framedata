# wubor-framedata-site

Static website for [The WuBor Patch](https://github.com/WuBoytH/The-WuBor-Patch) frame data.
Vite + Svelte 5, no backend: the pages read compact JSON from `public/data/`.

## Data

`public/data/` is generated by [wubor-framedata](https://github.com/WuBoytH/wubor-framedata)
and committed here. To refresh it, from that repo:

```sh
cargo run -q -- build   # (re)build data/{wubor,vanilla}/<fighter>.json from the mod + game files
cargo run -q -- site    # re-encode into ../wubor-framedata-site/public/data (path: `site_out` in wubor-framedata.toml)
```

Layout: `index.json` (fighter list, hitbox field order, generation date) and
`{wubor,vanilla}/<fighter>.json`. The format is described in `src/lib/types.ts`.

## Develop

```sh
npm install
npm run dev      # http://localhost:5173
npm run check    # svelte-check
npm run build    # → dist/
```

Routing is hash-based (`#/f/mario`, `#/f/mario/mario/game_attackairn`, `#/f/mario/cancels`)
and the Vite base is `./`, so `dist/` works from any path — GitHub Pages
(`.github/workflows/deploy.yml` publishes `main`), a subfolder, or `file://`.

## Move names

Moves are named from their script name by pattern (`game_attackairn` → Neutral
Air). Fighter-specific names live in **`src/data/move-names.ts`** — add an entry
under the fighter's id to rename a script (`game_specialn: 'Fireball'`), or
give `{ name, category }` to also move it to another section. Article scripts
are keyed `agent/script`; the `'*'` section applies to every fighter.
`ARTICLE_NAMES` in the same file renames an article's heading
(`mario: { mario_fireball: 'Fireball' }`).

Order within a category is automatic (jabs → dash → tilts; start → main → end
for specials, …). To pin it by hand, list scripts in **`src/data/move-order.ts`**
under the fighter: listed scripts go to the top of their category in that
order, the rest follow automatically.

## Showing and hiding things

**`src/data/visibility.ts`** holds include/exclude lists for the fighter page:
`PARAMS` (sidebar keys), `MOVES` (script names, `agent/script` for
articles) and `ARTICLES` (whole article agents), each with a `'*'` section
and optional per-fighter sections.
`exclude` hides matches; a non-empty `include` shows only matches. Patterns
are exact strings, `*` wildcards, or regexes. Hidden moves still open from a
direct link.

## Pages

* **Home** — fighter grid with search and per-fighter modded-script counts.
* **Fighter** — moves by category with startup, active frames, FAF, total, damage,
  landing lag and autocancel for aerials; articles; the mod's param changes.
* **Move** — frame strip (hitboxes, autocancel, cancel windows, intangibility,
  FAF), per-window hitbox tables, cancels, notes, and the raw script events.
  Scripts with runtime branches show one tab per variant.
* **Cancels** — the fighter's custom-cancel rules and every cancel window they
  produce.
